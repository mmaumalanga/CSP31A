1. What are searching and sorting?

RememberUnderstand

Searching

Locating an item in a list, such as an array or a vector. The result is the item's position (index), or -1 if it isn't there.

Sorting

Arranging values into an order: ascending (smallest to largest, like 2, 5, 9) or descending (largest to smallest, like 9, 5, 2).
Real worldFinding one student among 20,000

Delta's registration system has to find your student ID among about 20,000 records. With a linear search, it checks records one at a time: about 10,000 checks on average, and all 20,000 if your ID isn't there. If the records are sorted by ID, a binary search finds you in at most 15 checks, because each check cuts the remaining records in half (215 = 32,768 > 20,000). That's why your phone's contact list, a dictionary, and a database index all keep their data sorted.

2. Linear (sequential) search

UnderstandApply Start at index 0 and step through the array until you find the value or run out of elements.

// Returns the index of value, or -1 if it is not in the array
int linearSearch(const int list[], int size, int value) {
    bool found = false;
    int position = -1;
    int index = 0;
    while (index < size && !found) {
        if (list[index] == value) {
            found = true;
            position = index;
        }
        index++;
    }
    return position;
}

Tradeoffs: Linear search is easy to understand and works on an array in any order. But it's slow on large arrays: for N elements it makes about N/2 comparisons on average when the value is there, and all N when it isn't.

3. Binary search: worked example

UnderstandApply Follow the reasoning. You'll trace one on your own right after.

Binary search requires a sorted array. It looks at the middle element. If that's the value, it's done. Otherwise, it throws away the half that can't contain the value and repeats on the half that can.

int binarySearch(const int array[], int size, int value) {
    int first = 0, last = size - 1, position = -1;
    bool found = false;
    while (!found && first <= last) {          // <= so a 1-element range is still checked
        int middle = (first + last) / 2;
        if (array[middle] == value) {
            found = true;
            position = middle;
        }
        else if (array[middle] > value)
            last = middle - 1;                   // value can only be in the LEFT half
        else
            first = middle + 1;                  // value can only be in the RIGHT half
    }
    return position;
}

Worked example: search for 45 in the sorted array {2, 4, 7, 10, 11, 45, 50, 59, 60, 66, 69, 70, 79} (indexes 0–12).

6. Common misconceptions

Misconception 1

"Binary search works on any array, and it's always faster."

Why it's wrong: Binary search decides which half to throw away by assuming everything left of the middle is smaller and everything right of it is larger. On an unsorted array that assumption is false, so it can discard the half that holds the value and wrongly report "not found." If the data isn't sorted, you have to sort it first, and sorting costs far more than one linear search. For a single search of unsorted data, linear search is the right choice.

Misconception 2

"The loop condition can be while (first < last)."

Why it's wrong: When the range shrinks to one element, first == last. With <, the loop stops before checking that last element. In the worked example above, 45 would be reported as not found even though it's at index 5. The correct condition is first <= last: keep going while at least one element is left.

1. Bubble sort

UnderstandApply Compare each pair of neighbors and swap them if they're out of order. After each pass, the largest remaining value has "bubbled" to the end.

Worked example: the first pass on {23, 78, 45, 8, 32, 56}

CompareOut of order?Array after this step
23 and 78No, leave them23 78 45 8 32 56
78 and 45Yes, swap23 45 78 8 32 56
78 and 8Yes, swap23 45 8 78 32 56
78 and 32Yes, swap23 45 8 32 78 56
78 and 56Yes, swap23 45 8 32 56 78

Pass 1 made 5 comparisons and 4 swaps. Now 78, the largest value, is in its final place, so pass 2 only needs to go up to index 4. That's the first improvement from the slides: shrink the inner loop by one each pass.

void swap(int& a, int& b) {        // pass by reference so the caller's values change
    int temp = a;
    a = b;
    b = temp;
}

void bubbleSort(int array[], int size) {
    bool moreToSwap;
    int last = size - 1;              // improvement 1: last unsorted index shrinks each pass
    do {
        moreToSwap = false;
        for (int i = 0; i < last; i++) {
            if (array[i] > array[i + 1]) {
                swap(array[i], array[i + 1]);
                moreToSwap = true;    // improvement 2: remember that a swap happened
            }
        }
        last--;
    } while (moreToSwap);             // no swaps in a pass means the array is sorted: stop early
}

Why the flag matters: On an array that's already sorted, the first pass makes no swaps, so moreToSwap stays false and the sort stops after just n − 1 comparisons. Without the flag, it would keep making every comparison anyway.

2. Selection sort

Understand Find the smallest remaining element and swap it into the next position.

void selectionSort(int array[], int size) {
    for (int start = 0; start < size - 1; start++) {
        int minIndex = start;
        for (int i = start + 1; i < size; i++)      // careful: start + 1, not start + start
            if (array[i] < array[minIndex])
                minIndex = i;
        swap(array[start], array[minIndex]);        // at most ONE swap per pass
    }
}

On {23, 78, 45, 8, 32, 56}, pass 1 finds the smallest value, 8, at index 3 and swaps it with 23: 8 78 45 23 32 56. Selection sort always makes the same number of comparisons, but it makes very few swaps: at most n − 1.

3. Insertion sort

Understand Build a sorted part one element at a time, like sorting a hand of playing cards.

void insertionSort(int array[], int size) {
    for (int i = 1; i < size; i++) {
        int key = array[i];                 // the value to insert
        int j = i - 1;
        while (j >= 0 && array[j] > key) {
            array[j + 1] = array[j];        // shift larger values one spot right
            j--;
        }
        array[j + 1] = key;                 // drop the key into the gap
    }
}

On already sorted (or nearly sorted) data, the inner loop stops right away, so insertion sort does very little work.

6. More misconceptions

Misconception 3

"All three sorts are O(n²), so they always take the same amount of work."

Why it's wrong: O(n²) describes how the worst case grows as n gets large. It doesn't mean equal work on every input. On already-sorted data, improved bubble sort and insertion sort each make only n − 1 comparisons, while selection sort still makes all n(n − 1)/2. Use the visualizer above to see it: for 6 sorted values that's 5 comparisons vs. 15.

Misconception 4

"swap(a, b) works fine with pass by value."

Why it's wrong: With void swap(int a, int b), the function swaps its own copies, and the array in the caller never changes. The parameters must be references, void swap(int& a, int& b), so the function works on the original array elements.
