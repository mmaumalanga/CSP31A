AnalyzeTask A: Why Didn't the GPA Change?

A student wrote this function to give everyone a bonus. After it runs, stu.gpa is still 3.2. Trace the code and explain exactly why, then state the one-character fix.

void addBonus(Student s)
{
    s.gpa = s.gpa + 0.3;
}

int main()
{
    Student stu = {123456, "Maria", 2, 3.2};
    addBonus(stu);
    cout << stu.gpa;   // prints 3.2, not 3.5
}
0 words (aim for 25+)
Expert reasoning: s is a value parameter, so the call copies every member of stu into a brand-new local struct. The function changes the copy's gpa, and the copy is destroyed when the function returns, so stu in main never changes. Fix: make it a reference parameter, void addBonus(Student &s). The call stays addBonus(stu);, with no & in the call.

EvaluateTask B: Choose and Defend a Function Header

The bookstore's printReceipt function displays a Textbook but must never change it. Which header is best? Pick one and justify it by comparing it with the other two.

(1) void printReceipt(Textbook b)
(2) void printReceipt(Textbook &b)
(3) void printReceipt(const Textbook &b)
0 words (aim for 30+)
Expert evaluation: (3) is best. (1) is safe, but it copies the whole struct, including the strings, on every call, which wastes time and memory. (2) avoids the copy, but the function could accidentally change the textbook, and the compiler wouldn't stop it. (3) gets both benefits: no copy, and the compiler blocks any change. Rule of thumb: pass a struct by const reference when the function only needs to read it.

CreateTask C: Design a Campus Parking Permit System

Scenario: Delta College Campus Police issue parking permits. Each permit has a permit number, an expiration year, a permit type (Student, Staff, or Motorcycle), and the vehicle it belongs to (make, model, license plate). Write C++ declarations that model this, plus a function that prints one permit.

Requirements: use an enum for permit type, a nested struct for the vehicle, a default value for at least one member, and a print function with an appropriate parameter type.

0 of 6 criteria met
enum PermitType { STUDENT, STAFF, MOTORCYCLE };

struct Vehicle
{
    string make;
    string model;
    string plate;
};

struct Permit
{
    int permitNum = 0;
    int expYear = 2027;            // default value
    PermitType type = STUDENT;     // enum member
    Vehicle car;                   // nested struct
};

void printPermit(const Permit &p)  // read-only, no copy
{
    string names[] = {"Student", "Staff", "Motorcycle"};
    cout << "Permit #" << p.permitNum
         << " (" << names[p.type] << ") expires " << p.expYear << endl;
    cout << p.car.make << " " << p.car.model
         << ", plate " << p.car.plate << endl;
}
Why this design works: the enum limits permit type to three valid values and works as an array subscript to look up a readable name. Making Vehicle a separate struct means it can be reused, for example in a citation system. The default values guarantee no garbage, and const Permit & avoids a copy while preventing accidental changes.
