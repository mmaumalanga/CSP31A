Loops & Repetition

Six sections build from the basic while loop up through nested loops and choosing the right loop for the job. Each section ends with a quick self-check. Then head to Flashcards, the Quiz, or the Matching activity to practice.

Printing "Welcome to C++!" five times by copy-pasting the same cout statement works - but it's tedious, and hopeless if you needed it 1,000 times. A loop is any section of a program that repeats itself, letting one block of code run over and over.

int count = 0; while (count < 100) { cout << "Welcome to C++!\n"; count++; }

The general form is while (loop-continuation-condition) { statements; }. The while loop is a pre-test loop: it checks the condition before each pass, so if the condition starts out false, the body may never execute at all.

⚠️ Common Misconception

"A while loop always runs at least once, just like a regular block of code." Not true. Because it's a pre-test loop, C++ checks the condition first. If that condition is false on the very first check, the loop body is skipped entirely - zero times, not once. (Contrast this with the do-while loop later in this module, which is guaranteed to run at least once.)

Watch Out for Infinite Loops

The loop body must contain code that eventually makes the condition false. Forgetting this creates an infinite loop:

int count = 1; while (count <= 5) { cout << "Hello\n"; } // count is never changed - this never stops!
✔️ Quick Self-Check

1. A while loop's condition is false the very first time it's checked. How many times does the loop body run?

2. What causes an infinite loop?

TypeDescription
Count-controlledRepeats a fixed, known number of times
Event-controlledRepeats an unknown number of times, ending when some condition (often a sentinel value) is met
🧩 Worked Example - Count-Controlled Summation
int count=0, sum=0, num, limit; cout << "How many numbers? : "; cin >> limit; while (count < limit) { cout << "Enter a number : "; cin >> num; sum += num; count++; } cout << "Sum is : " << sum;
Run 1limit=3, entering 10, 9, 21 → the loop runs exactly 3 times → Sum is : 40.
Run 2limit=-1 → count (0) < limit (-1) is false immediately, so the body never runs → Sum is : 0.
NoteThe counter (count) must always be initialized before the loop - here, to 0.

An event-controlled loop instead runs until a special sentinel value (like -1) tells it to stop - useful when you don't know in advance how many values the user will enter.

Summing integers entered from the keyboard until a sentinel (say, a negative number) is entered sounds simple - but it's easy to get subtly wrong. Three attempts, same goal: sum positive integers entered by the user.

⚠️ Common Misconception #1

"As long as the loop stops when it sees the sentinel, the sum must be correct." Not necessarily - the sentinel itself can accidentally get added in.

int sum=0, num=1; // initialize to be true while (num > 0) { cout << "Enter a number : "; cin >> num; sum = sum + num; // adds EVERY value read, including the sentinel! } cout << "Sum is : " << sum;

Entering 1, 2, 3, then -1 as the sentinel gives Sum is : 5 (1+2+3+(-1)=5) instead of the correct 6 - the sentinel got summed in before the loop ever re-checked the condition. The fix is to guard the addition: if (num > 0) sum = sum + num; - correct, but it re-checks that condition on every single iteration, which works but is inefficient.

🧩 Worked Example - The Priming Read Pattern

The efficient, correct fix reads once before the loop (the "priming read"), then again at the very end of the loop body (the "subsequent read"):

int sum=0, num; cout << "Enter a number : "; cin >> num; // Initial (priming) read while (num > 0) { sum += num; cout << "Enter a number : "; cin >> num; // Subsequent read } cout << "Sum is : " << sum;
TraceEntering 2, 4, 3, 1, 2, then -1: the sentinel (-1) is read after sum += num already ran for 2, so it's never added. Sum = 2+4+3+1+2 = 12 - correct, and the condition is only checked once per iteration.
⚠️ Common Misconception #2

"As long as I do a priming read before the loop, the order of statements inside the loop body doesn't matter." It does - badly.

int sum=0, num; cout << "Enter a number : "; cin >> num; // priming read: say the user enters 3 while (num > 0) { cout << "Enter a number : "; cin >> num; // reads the NEXT value BEFORE using the current one! sum = sum + num; }

Entering 3, 4, 5, then -1: the first value (3) is immediately overwritten by 4 before it's ever added to sum - it's silently lost. The result is Sum is : 8 (4+5+(-1)) instead of 12. The read and the "use the value" step must be in the right order relative to each other inside the loop body.

1. In the correct priming-read pattern, where does the "subsequent read" go?

2. What specifically goes wrong in Misconception #2's buggy version?

do { statement; } while (expression);

The do-while loop is a post-test loop: the body runs first, and the condition is checked after. That guarantees the body executes at least once - exactly what you want for a menu that should always show at least one time.

🌍 Real-World Application - A Menu-Driven Averaging Program
int score1, score2, score3; double average; char again; do { cout << "Enter 3 scores and I will average them: "; cin >> score1 >> score2 >> score3; average = (score1 + score2 + score3) / 3.0; cout << "The average is " << average << ".\n"; cout << "Do you want to average another set? (Y/N) "; cin >> again; } while (again == 'Y' || again == 'y');

Entering 45, 65, 73 gives an average of 61; the user then types 'y', and entering 89, 87, 71 gives 82.3333, before finally typing 'n' to stop. This "ask, then ask again?" pattern - common in real menu-driven software - is exactly what do-while is built for, since the menu must be shown at least once no matter what.

for (initial-action; loop-continuation-condition; action-after-each-iteration) { statement(s); }

Like while, the for loop is a pre-test loop - but it packages initialization, the test, and the update into one compact header.

🧩 Worked Example - Printing Squares 1 to 8
const int MIN = 1, MAX = 8; for (int i = MIN; i <= MAX; i++) cout << i << "\t\t" << (i * i) << endl;
i=11   1
i=44   16
i=88   64 — then i becomes 9, the condition i<=8 fails, and the loop ends.
Contrastfor (count=10; count<5; count++) never runs its body at all - the condition (10<5) is false on the very first, pre-test check.
KeywordEffectExample Output
continueSkips the rest of the current iteration's body and moves on to the next iterationfor(i=1;i<=5;i++){ if(i==3) continue; cout<<i; } → prints 1 2 4 5
breakExits the loop immediately, skipping all remaining iterationsfor(j=1;j<=5;j++){ if(j==3) break; cout<<j; } → prints 1 2

The comma operator can pack more than one expression into a for loop's initialization or update: for (x=1, y=1; x<=5; x++, y++) initializes and updates both x and y together.

A nested loop is a loop inside the body of another loop. Printing a 3-row by 5-column box of stars by copy-pasting three separate for loops works, but repeats the same code three times - wasteful, and unworkable for 100 rows. A nested loop fixes that:

int rows = 3, cols = 5; for (int i = 0; i < rows; i++) { for (int j = 0; j < cols; j++) { cout << "*"; } cout << endl; // needed after each row }

The total number of repetitions of the inner loop's body is the product of the two loops' repetition counts - here, 3 × 5 = 15 total stars printed.

🌍 Real-World Application - Generating a Multiplication Table
for (int i = 1; i <= 9; i++) { cout << i << " | "; for (int j = 1; j <= 9; j++) { cout << setw(3) << i * j; // display the product, aligned } cout << "\n"; }

The outer loop (i) walks down the rows 1\u20139; for each row, the inner loop (j) walks across all 9 columns, computing i * j each time - exactly the times-table tool used in classrooms everywhere. The outer loop runs 9 times, the inner loop runs 9 times for every outer pass, for 81 total multiplications.

✍️ Your Turn - Design It (Create)

Design the nested loop (pseudocode or C++) that would print a box of 4 rows by 6 columns of the character #. How many total # characters will be printed? Write your answer, then reveal a model solution.

int rows = 4, cols = 6; for (int i = 0; i < rows; i++) { for (int j = 0; j < cols; j++) { cout << "#"; } cout << endl; }
Total characters printed = rows × cols = 4 × 6 = 24.

Deciding Which Loop to Use

LoopBest suited for
while (pre-test)Validating input; reading a list terminated by a sentinel
do-while (post-test)Repeating a menu - something that must run at least once
for (pre-test)Situations where the exact number of iterations is already known
