1. Anatomy of a function

RememberUnderstand

A function is a group of statements that performs one specific task. Every C++ program has at least one: main(). You have already called library functions such as pow() and sqrt() from <cmath>. Now you'll write your own.

Writing your own function takes three pieces, and they must agree with each other:

#include <iostream>
using namespace std;

double cube(double);                 // 1. PROTOTYPE: declared before main, ends with ;

int main()
{
  double num = 3.0;
  double cubeVal = cube(num);         // 2. CALL: num is the ARGUMENT
  cout << cubeVal << endl;            // prints 27
  return 0;
}

// Purpose: returns the cube of a number
// Pre:  answer holds any double
// Post: returns answer * answer * answer
double cube(double answer)            // 3. DEFINITION: header + body, no ;
{
  return answer * answer * answer;    // answer is the PARAMETER
}
PieceWhat it doesTip
PrototypeTells the compiler the return type, name, and parameter types before the function is used.Parameter names are optional here. Put prototypes above main().
CallRuns the function. Arguments are matched to parameters by position.Use or store the returned value: x = cube(2.0);
DefinitionThe header plus the body that does the work.Copy the prototype, remove the ;, add the { } body.

Arguments vs parameters

Arguments (actual parameters) are the values in the call: num. Parameters (formal parameters) are the variables in the header that receive them: answer.

Naming a function

Use a verb + noun: calcAverage(), getInput(), printReport(). It reads as an action and is clearer than average().

A void function performs a task but returns nothing, like void printLine(int width). A value-returning function uses return to send exactly one value back to the caller.

Common misconception: "I can return two values with return num1, num2;"

This compiles, which makes it sneaky. The comma here is the comma operator: it evaluates num1, throws it away, and returns only num2.

Correct reasoning: a C++ function returns one value. To send back more than one result, use reference parameters (lesson 3), for example void findMinMax(int a, int b, int& lo, int& hi).

2. Worked example: functional decomposition

UnderstandApply

Functional decomposition breaks a program into small functions that each do one job. Stepwise refinement means you build and test them one at a time. Here is the full process, with the reasoning at each step, for the problem in the slides.

Worked example: find the longest side of a right triangle
  1. Write the plan in plain steps. Read sideA, read sideB, compute sideC = √(sideA² + sideB²), print the result. Reason: each step is a candidate function. If a step is a single clear task, it deserves a verb + noun name.
  2. Name the functions. getInput(), findSideC(), printResult(). main() just calls them in order. Reason: getInput() is called twice, so writing it once avoids redundant code. Its prompt stays generic so it can be reused for any side.
  3. Decide inputs and outputs for each. getInput needs nothing and returns a double. findSideC needs two doubles and returns one. printResult needs three values and returns nothing, so it's void. Reason: the return type answers "what comes back?"; the parameter list answers "what does it need to do its job?"
  4. Write all prototypes, then use stubs. A stub is a placeholder body that returns a fixed test value, so main() (the driver) compiles and runs right away. Reason: if the call mechanics work with a stub, any later bug is inside the one function you're finishing, not in how functions connect.
  5. Replace one stub at a time and test.
#include <iostream>
#include <cmath>
using namespace std;

double getInput();
double findSideC(double, double);
void   printResult(double, double, double);

int main()                              // the driver
{
  double sideA = getInput();
  double sideB = getInput();
  double sideC = findSideC(sideA, sideB);
  printResult(sideA, sideB, sideC);
  return 0;
}

double getInput()
{
  double value;
  cout << "Enter a side length: ";
  cin >> value;
  return value;
}

double findSideC(double a, double b)
{
  // STUB version was:  return 5.0;
  return sqrt(a * a + b * b);           // or hypot(a, b)
}

void printResult(double a, double b, double c)
{
  cout << "Sides " << a << " and " << b
       << " give hypotenuse " << c << endl;
}
Trace it with inputs 3 and 4:
getInput() → 3.0  |  getInput() → 4.0  |  findSideC(3.0, 4.0): a=3, b=4 → sqrt(9 + 16) = 5.0  |  printResult prints 5

Notice the parameter names a and b don't need to match the argument names sideA and sideB. Only the position and type matter.

A program reads three quiz scores and prints their average. Following the same steps, write the prototype, the definition of calcAverage, and the call that stores the result in avg using variables q1, q2, q3.

    double calcAverage(double, double, double);   // prototype

avg = calcAverage(q1, q2, q3);                    // call

double calcAverage(double s1, double s2, double s3)   // definition
{
  return (s1 + s2 + s3) / 3.0;
}

    3. Pass by value vs pass by reference

    UnderstandApplyAnalyze

    By default, C++ passes arguments by value: the argument's value is copied into the parameter. The parameter is a separate local variable in the function's own stack frame, so changing it has no effect on the caller. The classic example is swap().

    // Pass by value: does NOT work
void swap(int n1, int n2)
{
  int temp = n1;
  n1 = n2;
  n2 = temp;
}
    // Pass by reference: works
void swap(int& n1, int& n2)
{
  int temp = n1;
  n1 = n2;
  n2 = temp;
}

    Step through what happens in memory when main() calls swap(num1, num2) with num1 = 23 and num2 = 45. The addresses (100, 104, …) are illustrative.

    Common misconception: "If the function changes its parameter, the caller's variable changes too."

    With pass by value, n1 and n2 are copies living in swap()'s own stack frame. The swap happens correctly inside the function, and then the frame is destroyed when the function returns. num1 and num2 in main() were never touched.

    Correct reasoning: only a reference parameter (int& n1) makes the parameter another name for the caller's variable. Then n1 is num1, and changes stick.

    "Returning" more than one value

    Since a function returns only one value, reference parameters are how you send back several. The slides' findSum() keeps running totals of positive and negative numbers:

    int  findSum(int num);                                 // NO: can return only one total
void findSum(int num, int totalPos, int totalNeg);   // NO: copies are destroyed
void findSum(int num, int& totalPos, int& totalNeg); // YES

void findSum(int num, int& totalPos, int& totalNeg)
{
  if (num > 0) totalPos += num;
  else         totalNeg += num;
}

    Rules for reference parameters

    Syntax

    Put & on each reference parameter in both the prototype and the header. The spacing (int& x or int &x) doesn't matter. The call looks normal: swap(num1, num2);

    What you can pass

    The argument must be a variable. swap(5, 7) or swap(a + 1, b) won't compile, because a literal or expression has no storage to refer to.

    Use a reference only when the function's job is to change the caller's variable. If it only needs to read a value, pass by value (or use a const reference for large objects like string) so it can't change the data by accident.

    Self-check 3

    4. Scope, static, overloading, and defaults

    UnderstandAnalyzeEvaluate

    Scope: where a name can be used

    Local variables and parameters exist only inside their function (or inner block, such as a for loop). Global names are declared outside every function and are visible everywhere after the declaration. Good practice: make constants and prototypes global, but not variables.

    void printSum(int, int);

int main()
{
  int a = 5, b = 7;
  printSum(a, b);
  cout << x;              // ERROR: x is undeclared here
  return 0;
}

void printSum(int x, int y)   // x and y are local to printSum
{
  cout << "sum is " << x + y;
}

    Static local variables: keep a value between calls

    An ordinary local variable is created fresh on every call and destroyed on return. A static local is initialized once, on the first call, and keeps its value for the life of the program.

    Real-world application: the campus coffee cart's card reader

    The coffee cart's register program charges a student's meal card and counts how many sales it rang up today. Look at how each design choice maps to something you learned:

    const double TAX_RATE = 0.0825;             // global CONSTANT: fine

bool chargeCard(double& balance, double price)  // balance must change: reference
{
  static int salesToday = 0;                 // survives between calls
  double total = price * (1 + TAX_RATE);     // price only read: by value
  if (total > balance) return false;        // declined
  balance -= total;
  salesToday++;
  cout << "Sale #" << salesToday << " approved\n";
  return true;
}

    If balance were passed by value, every student's card would be charged in the function but never actually go down. That's the slides' "balance is always 1000" bug. If salesToday weren't static, every receipt would say "Sale #1".

    Function overloading

    Several functions can share a name if their signatures differ: the number, types, or order of parameters. The compiler picks the one that best matches the arguments.

    int    findMax(int a, int b);
double findMax(double a, double b);
int    findMax(int a, int b, int c);

findMax(3, 8);        // calls the int, int version
findMax(2.5, 1.5);    // calls the double, double version
findMax(1, 9, 4);     // calls the three-int version

    Common misconception: "Two functions can differ only by return type."

    int getValue(); double getValue(); won't compile. At a call like getValue();, the compiler looks only at the name and the arguments to choose a function, and both versions look identical.

    Correct reasoning: the return type is not part of the signature. Overloads must differ in their parameter lists. Also watch for ambiguous calls: with f(int, double) and f(double, int), the call f(1, 2) matches both equally well, so it's an error.

    Default arguments

    A default argument is used when the caller leaves that argument out. Defaults go in the prototype, and they must be the rightmost parameters.

    void printLine(int width = 20, char symbol = '-');   // prototype holds defaults

printLine();          // 20 dashes
printLine(10);        // 10 dashes
printLine(10, '*');   // 10 stars

void bad(int a = 1, int b);                             // ERROR: default not rightmost
