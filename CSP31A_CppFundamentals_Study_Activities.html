A data type describes the set of possible values and operations for a piece of data. A variable is a named storage location in memory (RAM) \u2014 unlike a file on disk, memory is volatile and loses its contents when power is off.

🧩 Worked Example \u2014 Binary Storage

A char variable named letter stores the bit pattern 01000001. What decimal value does that represent?

Convert01000001 in binary = (0×128)+(1×64)+(0×32)+(0×16)+(0×8)+(0×4)+(0×2)+(1×1) = 64+1 = 65.
Interpret65 is also the ASCII code for the character 'A' \u2014 which is exactly what a char variable holding this bit pattern would print.

Type coercion happens automatically: a "shorter" data type is promoted to a "larger" one when needed for an operation.

🧩 Worked Example \u2014 Integer vs. Floating-Point Division
10 / 4Both operands are int, so C++ performs integer division and truncates: result is 2.
10.0 / 4One operand (10.0) is floating point, so the other is promoted, giving a floating-point result: 2.5.
10 / 4.0Same promotion applies regardless of which side is floating point: 2.5.

The floating-point types are float, double, and long double. Floating-point literals like 3.14159 are double by default \u2014 append f to force float (3.14159f) or L to force long double.

The sizeof() Function

The sizeof() function returns the number of bytes a specified data type occupies \u2014 e.g. sizeof(int) typically returns 4.

Identifier rules: the first character must be alphabetic or an underscore; later characters may be alphabetic, digits, or underscores; and identifiers are case-sensitive (total and Total are different names).

The assignment operator (=) assigns the right-hand value to the left-hand variable \u2014 it is not a test for equality. Modern C++11 brace initialization (int x{5};) checks type compatibility strictly: int b{2.5}; is a syntax error, since a fractional value can't safely fit an int this way.

🧩 Worked Example \u2014 Tracing Increment/Decrement
int count = 5; cout << count; // line A cout << count++; // line B cout << ++count; // line C
Line ASimply prints the current value: 5.
Line Bcount++ is postincrement: it prints the original value first, 5, then increments count to 6 afterward.
Line C++count is preincrement: it increments count first (6 → 7), then prints the new value: 7.

Augmented assignment operators combine an operation with assignment: i += 8; is equivalent to i = i + 8; (similarly for -=, *=, /=, %=).

A constant is declared with the const keyword and cannot change during execution, e.g. const double TAX_RATE = 0.0675; \u2014 often named in uppercase by convention.

Overflow occurs when a number exceeds a type's maximum limit. Underflow (technically "integer wrap-around") occurs when a value drops below the minimum.

🧩 Worked Example \u2014 Watching an unsigned short int Overflow
unsigned short int count = 65534; // max is 65,535 count = count + 1; cout << count; // line 1 count = count + 1; cout << count; // line 2
Line 165534 + 1 = 65535, still within range. Prints 65535.
Line 265535 + 1 would be 65536 \u2014 outside the type's range (0 to 65,535). The value wraps back around to 0. This is overflow in action.
✍️ Your Turn \u2014 Apply It

Using the same reasoning, what would cout << count; print if the code ran one more count = count + 1; after line 2 above (i.e., a third increment)? Write your answer and reasoning, then reveal the answer.

After line 2, count = 0. Adding 1 gives 1 \u2014 well within range, so no further wrap-around happens this time. Overflow only occurs right at the moment a value would exceed the type's maximum.

Precedence & Associativity

2 + 6 * 5 equals 32, not 40 \u2014 multiplication has higher precedence than addition, so 6*5 is evaluated first. When operators share the same precedence, associativity decides the order: most arithmetic operators are left-to-right, so 5*6.0/4*2 evaluates as ((5*6.0)/4)*2 = 15.0, not 3.75.

cin reads from standard input (the keyboard) using the extraction operator (>>). Whitespace between values is ignored, but cin stops working as soon as it encounters an invalid value for the target type.

Scope: variables declared outside and before main() have global scope and are visible everywhere \u2014 which is why only constants or function prototypes should typically be global (an ordinary global variable can be changed by any function, with no protection). Variables declared inside a function are local to it; keeping variables local is good practice.

🌍 Real-World Application \u2014 Simulating a Die Roll

Games and multi-factor authentication codes both rely on random numbers. C++'s srand() sets a starting seed (which must differ each run, or the same "random" sequence repeats every time), and rand() then generates pseudo-random values. To simulate rolling a six-sided die, the raw output of rand() is mapped into the range 1 to 6 inclusive \u2014 a practical example of combining a math library function with a real constraint (a die only has 6 faces).

⚠️ Common Misconception

"Good programming style is just about looks \u2014 it doesn't matter to the compiler." That's actually correct about the compiler (indentation, spacing, and blank lines don't change how a program runs) \u2014 but style still matters enormously to people. Poor style (no comments, inconsistent indentation, unclear variable names) makes a program much harder for you or a teammate to read, debug, and maintain later, even though it compiles and runs identically either way.

⚠️ Common Misconception

"If my program compiles with no errors, it must be correct." Compiling successfully only rules out syntax errors. A program can compile perfectly and still contain a logic error (like sum = num1 = num2; instead of sum = num1 + num2;) that produces the wrong result every time it runs \u2014 or a run-time error (like a division by zero) that only shows up under certain conditions. Compiling clean is necessary, but never sufficient, for correctness.
