Selection Control Structure

Section 1 · Remember / Understand

1. The if‑else Statement

An if statement lets a program conditionally execute or skip a statement. The controlling expression is anything that evaluates to true or false — in C++, 0 means false and any nonzero value means true.

if (x >= 0) cout << "Non-negative"; else cout << "Negative";

The else branch is optional — a bare if with no else is perfectly valid. To run more than one statement inside a branch, group them in braces { } to form a block:

if (score > 90) { grade = 'A'; cout << "Good Job!\n"; }

⚠ Common Misconception #1 — = vs ==

if (x = 10) looks like a comparison but it is an assignment. It sets x to 10 and the expression evaluates to 10 (nonzero → true), so the branch always runs, silently overwriting x. Use == to compare and = only to assign.

⚠ Common Misconception #2 — the stray semicolon

if (x > 0);
   cout << "Positive"; — that semicolon right after the condition ends the if with an empty statement. The cout line is no longer part of the if at all — it runs every time, unconditionally.

✅ Quick self-check

Given int x = 7;, what does if (x = 0) cout << "zero"; print?

Nothing prints. x = 0 is an assignment; it sets x to 0 and the expression's value is 0 (false), so the branch is skipped — but x is now permanently 0, which is itself a bug.
Section 2 · Understand / Apply

2. Relational & Logical Operators

Relational operators compare two operands and produce a Boolean result:

> Greater than >= Greater than or equal to < Less than <= Less than or equal to == Equal to != Not equal to

Logical operators combine relational expressions into more complex ones:

! NOT — reverses a value: true becomes false, false becomes true && AND — true only if both expressions are true || OR — true if either expression is true // precedence, highest to lowest: ! then && then ||

Worked example — given int x = 12, y = 5, z = -4;, reason through each expression left to right:

(x > y) && (y > z) // 12>5 is true, 5>-4 is true → true && true → TRUE (y > x) && (y > z) // 5>12 is false → short-circuits → FALSE (x <= z) || (y == z) // 12<=-4 false, 5==-4 false → false||false → FALSE !(x >= z) // 12>=-4 is true, ! flips it → FALSE

Notice the second line: once (y > x) is false, C++ never even bothers to check (y > z) — this is called short-circuit evaluation. It matters for performance, and it is essential when the second half of an expression is unsafe to evaluate on its own, such as a divisor check: if (divisor != 0 && total / divisor > 10).

✅ Quick self-check

With the same x=12, y=5, z=-4, what does (y != z) || (x <= z) evaluate to?

TRUE. y != z is 5 != -4, which is true — and since this is an ||, C++ short-circuits immediately and never evaluates x <= z at all.
Section 3 · Apply / Analyze

3. Nested if‑else and the Dangling Else

A nested if is an if statement placed inside the branch of another if, used when more than one condition must be tested in sequence. This is where indentation can lie to you: C++ doesn't care about whitespace — an else is always paired with the closest preceding if that doesn't already have an else, regardless of how the code is indented.

if (x > 10) if (x > 0) cout << "Positive"; else cout << "Not greater than 10";

Fully worked trace — suppose x = 5:

  1. The outer condition x > 10 is tested first: 5 > 10 is false.
  2. Because it's false, the entire statement controlled by the outer if is skipped.
  3. That controlled statement is the whole inner if/else — the else is bound to the inner if (x > 0), not the outer one, even though the indentation makes it look otherwise.
  4. So when the outer test fails, nothing prints at all — not "Positive", and not "Not greater than 10".

To force the else to pair with the outer if instead, wrap the inner if in braces so it can no longer "steal" the else:

if (x > 10) { if (x > 0) cout << "Positive"; } else cout << "Not greater than 10";

For a series of mutually exclusive conditions, prefer an if / else if / else chain, which tests conditions top to bottom and stops at the first match:

if (score >= 90) grade = 'A'; else if (score >= 80) grade = 'B'; else if (score >= 70) grade = 'C'; else if (score >= 60) grade = 'D'; else grade = 'F';

Why order matters: because the chain stops at the first true branch, once score >= 90 has already tested false, every later branch already "knows" the score is under 90 — so re-checking an upper bound like score >= 80 && score <= 100 is redundant. This mirrors the DRY (Don't Repeat Yourself) principle: don't test a condition the control flow has already guaranteed.

✅ Quick self-check

In the dangling-else example above, if x = 15, what prints?

"Positive" prints. x > 10 is true (15>10), so we enter the outer branch, which is the inner if (x > 0): 15>0 is also true, so cout << "Positive"; runs. The else never fires because the inner if succeeded.
Section 4 · Apply / Evaluate

4. switch and the Ternary Operator

A switch statement is an alternative to a long if/else if chain when you're comparing one integer-type expression (int, char, enum — not a float, string, or a range) against several constant values:

switch (expression) { case exp1: statement1; break; case exp2: statement2; break; ... default: statementN; }

Each matching case transfers control to its statement and then keeps executing forward — through the following cases — unless a break stops it. Omitting break is legal C++ but almost always a bug, called "fall-through." default is optional but recommended, so an unmatched value is still handled gracefully.

The ternary (conditional) operator ?: is a compact expression form of if/else that produces a value rather than choosing a statement to run:

// condition ? valueIfTrue : valueIfFalse; string status = (score >= 60) ? "Pass" : "Fail"; // equivalent longhand: if (score >= 60) status = "Pass"; else status = "Fail";

🌍 Real-world application — a menu-driven ATM program

Picture a simple ATM: it displays a numbered menu (1 Check Balance, 2 Withdraw, 3 Deposit, 4 Exit), reads the customer's choice, and must branch to the right action. A switch is the natural fit because the menu choice is a single integer being compared against a short list of exact values, and default gracefully catches an invalid keypress like 9. Before acting on the choice at all, the program should validate the input — is it a real menu option, is a requested withdrawal within the account's balance and daily limit, is a deposit amount positive — because bad output always starts with bad, unchecked input.

⚠ Common Misconception #3 — comparing strings/characters like numbers "just works, so it's the same as comparing text visually"

Characters and string objects in C++ are compared using their underlying ASCII values, not alphabetical intuition alone. 'A' < 'B' is true because 65<66 — that part matches intuition — but lowercase letters have higher ASCII codes than uppercase, so 'a' > 'A', and "apple" < "Banana" is actually false, which surprises many beginners expecting simple alphabetical order.

✅ Quick self-check

A switch statement has three case labels but no break anywhere, and the input matches the first case. What happens?

All three cases' statements execute, one after another — the program "falls through" every case (and default, if present) after the first match, because nothing tells it to stop.
